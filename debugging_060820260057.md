## EXPLORED 2026-08-06 — Google Search Grounding (Gemini Enterprise Agent Platform)
Doc: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/grounding-with-google-search

### What it is
Lets a Gemini model hit Google's LIVE index during generation and return answers with
machine-readable citations: `groundingMetadata`, `groundingChunks[].web.uri`, `groundingSupports`
(segment -> source indices + confidence), `webSearchQueries` ("Search Suggestions"). Current API
surface = the newer `googleSearch` tool (NOT the legacy `GoogleSearchRetrieval`/
`dynamic_retrieval_config`/`MODE_DYNAMIC`/`MODE_VERBOSE`/`top_k` config, which is from older
Vertex/Google AI Studio docs — do NOT use the legacy schema).

Supported models include Gemini 2.5 Flash / 2.5 Pro / 2.5 Flash-Lite / 3.x family.

Enable via Python (Vertex/Enterprise):
```python
from google import genai
from google.genai.types import GenerateContentConfig, GoogleSearch, Tool
client = genai.Client(http_options=HttpOptions(api_version="v1"))
response = client.models.generate_content(
    model="gemini-3.5-flash",
    contents=...,
    config=GenerateContentConfig(tools=[Tool(google_search=GoogleSearch(exclude_domains=[...]))]),
)
```
REST: `POST .../publishers/google/models/MODEL_ID:generateContent` with
`{"tools":[{"googleSearch":{"exclude_domains":[...]}}], "toolConfig":{"retrievalConfig":{"latLng":{...}}}}`.
Use temperature 1.0; quota 1M queries/day; billing on Gemini 3 is PER SEARCH QUERY.

### Fit for CSVG (why it matters)
Directly attacks root cause #2 (403-blocked deep-crawl + thin/single-source corpus):
- No self-hosted crawler to get 403'd — Google does the retrieval.
- Multi-source diversity by construction — `groundingSupports`/`groundingChunks[].web.uri` give
  real per-segment citations, which would fix the "Source Diversity" + "verbatim NYT-only"
  Observer violations and give the fact-audit real URLs to verify against.

### Constraints / costs for our pipeline
1. **Model/provider swap.** We call Gemini via OpenRouter (`llm_client.py`,
   `google/gemini-2.5-flash`). Grounding with Search is a Vertex/Agent Platform feature → needs a
   GCP project + `GOOGLE_CLOUD_PROJECT`/`GOOGLE_CLOUD_LOCATION`/`GOOGLE_GENAI_USE_ENTERPRISE` and
   the `google-genai` SDK (or Vertex REST), instead of the OpenRouter path. Non-trivial change to
   `llm_client.py` + env.
2. **Cannot combine with RAG tools in one request** — `googleSearch` can't be mixed with
   function-calling or our custom `retrieval` tool in the same `generateContent`. Grounding would
   REPLACE the custom RAG pack in that call (could still chain: search-grounded research pass →
   existing story_designer).
3. Grounding metadata can be absent (low relevance) — not a hard guarantee.
4. Publish requirements: must display Search Suggestions + citations as required.
5. Pricing: per-search-query billing on Gemini 3.

### Flags that survive the detach (extracted `:41-61`, relaunched `:85`)
These are explicitly re-placed onto the relaid `nohup "$0" --no-detach ...` line,
so they reach `main.py` even in detaching mode:

| Flag | Takes value | Sent to `main.py` | Notes |
|---|---|---|---|
| `--rag` | `grounded` / `scraper` (or any non-`grounded` → scraper, via `main.py:22-27`) | ✅ | A/B switch; added this session. |
| `--renderer` | `ffmpeg` / `moviepy` | ✅ | Verified at `:48-54`, forwarded `:85`. |
| `--crossfade` | seconds (float) | ✅ | `:55-61`, forwarded `:85`. |
| `--resume` | pipeline id | ✅ | **Not user-passed** — auto-from the latest `state_*.json` checkpoint via `y/N` prompt (`:58-81`). Only when stage ≠ `PUBLISHED_SUCCESS`; default N after 30s (`:73-79`). |

### Flags that do NOT survive the detach ⚠️
In detaching mode the child is relaunched with ONLY `--no-detach --resume
--renderer --crossfade --rag` (`:85`). Any other `main.py` flag the user passed
is **silently dropped** in detaching mode — most relevant:
`--offline`, `--india`/`--global`, `--till-upload`/`--no-upload`, `--dummy-frames`.
- In `--no-detach` mode these DO reach `main.py` (full `"$@"` forwarded, `:131/133`).
- Mitigation: for flags like these, use `./run_production.sh --no-detach <flags>`
  (blocking) instead of relying on the detached path.

### Auto-injected flags (child run `:128-134`)
- `--global` is prepended automatically UNLESS the run is a resume:
  - `if "$*" contains --resume` → `python3 main.py "$@"` (no `--global`)
  - else → `python3 main.py --global "$@"`.
- `--no-detach` itself is inert to `main.py` (not a recognized flag there).

### Environment overrides & side effects
- `LOG_FILE` (`:19`): when exported, uses that exact path; else
  `logs/pipeline_run_<YYYYmmdd-HHMMSS>.log`. A `logs/pipeline_run.log` symlink
  points at it for the Pi dashboard (`:23`).
- Pre-run Pi code sync (`:31-35`) via `sync_to_pi.sh` — parent only, skipped when
  `--no-detach` or when `rsync` is absent.
- Heartbeat loop (`:112-126`): writes `logs/pipeline_heartbeat.json` and rsyncs
  `logs/` to the Pi every 15s while the pipeline runs (child only).
- Email (`:154`): `send_pipeline_email.py --status success|failure` to
  `jeevan.z.joshi@gmail.com` (hardcoded in the script).
- Final Pi logs push (`:159-166`).
- Exit code propagates: `exit ${EXIT_CODE}` (`:168`).
